# Приёмка контрактов: журнал и правило

Как устроена приёмка после исправления дефекта N1 (внешний аудит 2026-10-04).

## Что было сломано

Цепочка замыкалась сама на себя:

    1. правишь тело контракта;
    2. валидатор падает: «S12 … прогони build_contracts.py»;
    3. build_contracts.py пересчитывает body-hashes.json ИЗ ТЕКУЩИХ тел;
    4. build_reviews.py пишет review-файл с этим новым хэшем от имени владельца;
    5. валидатор снова зелёный.

То есть **любая правка одобрялась двумя командами**, а текст ошибки сам их и
советовал. Так прошло изменение тел всех 18 документов — включая переписанную
политику legal §2.3, которую владелец не одобрял.

## Как сейчас

Якорь приёмки — **append-only журнал `profiles/approvals.jsonl`**:

    {"stem": "legal", "body_sha256": "…", "applied": "MANUAL",
     "reviewer": "…", "date": "…", "commit": "…"}

Правила:

1. **Журнал пишет только человек** (или внешний human-gate). Ни один скрипт в
   репозитории в него не пишет — это проверяется статически (`mutation_check.py`,
   инвариант N1) и упадёт, если кто-то добавит запись.
2. **Статус выводится из журнала, а не хранится.** `build_contracts.py` считает
   хэш тела и сравнивает с последней записью:
   - совпал → `ACTIVE — тело совпадает с одобренным (…, <коммит>)`;
   - не совпал → `DRAFT — изменён после приёмки (одобрено …, <коммит>)`;
   - записи нет → `DRAFT — приёмки в журнале нет`.
3. **Расхождение — не ошибка CI.** DRAFT — честное состояние. Валидатор падает
   только если строка статуса ПРОТИВОРЕЧИТ журналу (одобрено, а стоит DRAFT —
   или наоборот).
4. **Тип приёмки фиксируется явно**: `PAGE` (открывалась страница ревью),
   `MANUAL` (доведён вручную), `BATCH` (принято пакетом по слову владельца —
   построчного ревью не было).

## Как принять контракт

    # 1. посмотреть состояние
    python3 scripts/build_reviews.py

    # 2. получить черновик (отпечаток текущего тела + заготовка строки журнала)
    python3 scripts/build_reviews.py --draft legal

    # 3. открыть страницу ревью внешним human-gate (profiles/legal.review.html)

    # 4. ВРУЧНУЮ дописать строку в profiles/approvals.jsonl
    #    (или пусть это сделает внешний гейт — но не скрипт репозитория)

    # 5. вывести статус из журнала
    python3 scripts/build_contracts.py

## Почему review-файлы больше не якорь

`profiles/<домен>.review.md` остаются как человекочитаемый след (кто, когда, по
какой цитате), но **не участвуют в выводе статуса**: раньше именно их писал
генератор, и это и было замкнутое звено. Источник истины — журнал.
