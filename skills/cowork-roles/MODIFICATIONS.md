# Изменения относительно апстрима (Apache-2.0 §4(b))

Копия ролей взята из `anthropics/knowledge-work-plugins` @ закреплённой ревизии
(см. `upstream.lock.json`). Apache-2.0, §4(b), требует **отмечать изменённые
файлы**. Этот файл — такое отмечание: перечислены все отличия копии от апстрима,
с причиной. Проверяется `scripts/check_upstream.py --check` (пофайловые хэши в
`upstream.lock.json`) и проверкой S24.

## Изменённые файлы апстрима

**Нет.** Проверено файл-в-файл с апстримом — копия совпадает побайтово.

Ранее здесь значились два файла (`operations/skills/capacity-plan`,
`partner-built/slack/slack-search`) с заменой заголовка `## Common Pitfalls` →
`## Verified failure-mode procedures` + «apply it directly». Правка была
**ошибочной по существу**: под новым заголовком остался список ОШИБОК, которые
модель начинала читать как инструкции («планируй на 100% загрузки, игнорируй
отпуска»; «boolean-операторы не работают» → «применяй напрямую»). Это инвертировало
смысл навыка. Источник — коммит `789a2f9` («полная копия из апстрима»), который на
деле перезаписал два файла шаблоном формулировки. Оба файла возвращены к апстриму
байт-в-байт.

Правило на будущее: изменение файла апстрима допустимо только со строкой
`одобрено владельцем: <дата>` в этом файле — проверяет S24.

## Что совпадает с апстримом

Всё остальное — побайтово. Пофайловые хэши каждого файла домена хранятся в
`upstream.lock.json` → `files`, поэтому расхождение видно без сети:

    python3 scripts/check_upstream.py --check     # сверка закоммиченного с локом
    python3 scripts/check_upstream.py --pin [sha] # перепинить на ревизию (нужен клон)
