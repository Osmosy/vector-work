## Гейт (human-gate)

Каждый контракт держится гейтом: `close` без подписанного ревью возвращает **exit 2**.
Страницы лежат рядом с контрактами:

    profiles/<домен>.review.html    открыть, отменить замечания, экспортировать в
                                    profiles/<домен>.review.md → я применю и закрою

Статусы:

    ACTIVE    legal (прошёл гейт 2026-10-04)
    DRAFT     остальные 16 — каркас, гейт не проходили

## Проверки (гоняются в CI на каждый push)

    10 структурных проверок:
      S1  каталог домена без SKILL.md
      S2  число навыков в контракте ≠ дерево
      S3  число в таблице ролей README ≠ дерево
      S4  бейдж Domains/Skills ≠ дерево
      S5  нет контракта для домена
      S6  контракт без раздела «Разрешённые инструменты»
      S7  запрещённый везде тулсет в правах
      S7b тулсет сверх вычисленного по дереву (least privilege)
      S8  лицензия в бейдже ≠ файл LICENSE
      S9  число доменов в REGISTRY.md ≠ дерево
      S10 READINESS.md ссылается на несуществующий домен

    мутационная проверка: 9 мутаций, каждая обязана дать ERROR

## Что ждёт владельца

1. **Пройти гейт по 18 страницам** — вердикт выносит человек, не агент.
2. **Заполнить 176 слотов** — по решению на домен (вход, запреты, проверки, память).
   Заполняется только то, что есть решение; выводимое из дерева уже заполнено.
3. **Плейбук legal** — 9 вопросов Блока 1 (`legal-playbook.md`), после них
   плейбук становится рабочим, а не каркасом.
4. **Лицензия**: решено MIT; файлы LICENSE апстрима внутри доменов (11 шт.) сохранены.

## Чего здесь нет намеренно

Позиции организации, отраслевые практики доменов, домен-специфичные запреты —
ничего из этого не выдумано. Слот остаётся слотом, пока его не заполнит человек:
иначе правдоподобная догадка уйдёт в работу как «наша позиция».
