Приёмка привязана к телу контракта отпечатком `body_sha256`. Правка тела без нового
ревью роняет проверку S12. Тип приёмки (`PAGE`/`MANUAL`/`BATCH`) записан в каждом
`<домен>.review.md`: принятое пакетом описано как принятое пакетом, а не фразой
«посмотрел через страницу ревью» (такая фраза стояла в 16 файлах и противоречила
факту).

Страницы `.review.html` генерируются внешним human-gate и в репозиторий **не входят**
(`.gitignore`). Состояние гейта (`profiles/.human-gate/`) — тоже локальное.

      && python3 scripts/build_reviews.py && python3 scripts/build_readiness.py \
      && python3 scripts/validate_structure.py && python3 scripts/mutation_check.py

## Права (least privilege)

    база для всех                  file, skills, memory
    по требованию домена           connections, browser, terminal
    запрещено всем без исключений  delegate_task, cronjob_manage, computer_use

Браузер по тексту навыка **не доказывается**: эвристика давала ложные срабатывания
(«открывается в браузере», «сайт-визиты», «кликабельные карточки», «click-through
rate»), поэтому браузер не выдан ни одному домену и выдаётся только решением
владельца. Терминал получает один домен — `bio-research` (25 скриптов, вызов из навыка).

## Что ждёт владельца

1. **Заменить типовые `[Т]` на свои** — приоритет у 3 открытых решений
   (сторона по умолчанию, имя ревьюера YELLOW, типовая форма NDA), затем лимит
   ответственности и категории части B плейбука.
2. **Санкционные оговорки** (Часть C6 плейбука) — регулирование указное, единого
   акта нет; нужен перечень реальных контрагентов и режимов.
3. **Отозвать приёмку там, где типовое неверно.** Правка тела контракта требует
   нового ревью — S12 это форсирует, молча подменить содержание нельзя.
