## Приёмка (human-gate)

Якорь приёмки — append-only журнал `profiles/approvals.jsonl`. Его пишет **только
человек** (или внешний human-gate); ни один скрипт в него не пишет. Статус контракта
генератор выводит из журнала: хэш тела совпал с одобренным → `ACTIVE`, не совпал →
`DRAFT — изменён после приёмки`.

    сейчас: ACTIVE 0 / DRAFT 18

Все 18 документов сейчас в DRAFT: их тела изменились после пакетной приёмки от
2026-10-04 (коммит `847738e`) — добавлены строка владельца, ревизия апстрима,
синхронизированы sales и small-business, переписана политика legal §2.3.
Одобренные версии `847738e` лежат в журнале как исторические.

Раньше здесь была обратная ошибка: `build_contracts.py` пересчитывал
`body-hashes.json` из текущих тел, `build_reviews.py` писал review-файлы от имени
владельца, а текст ошибки S12 советовал прогнать генератор. Цепочка замыкалась сама
на себя — любая правка «одобрялась» двумя командами. Разбор: `docs/ACCEPTANCE.md`.

## Права (least privilege)

    база для всех                  file, skills, memory
    по требованию домена           connections, browser, terminal
    запрещено всем без исключений  delegate_task, cronjob_manage, computer_use

Браузер по тексту навыка **не доказывается**: эвристика давала ложные срабатывания
(«открывается в браузере», «сайт-визиты», «кликабельные карточки», «click-through
rate»), поэтому браузер не выдан ни одному домену и выдаётся только решением
владельца. Терминал получает один домен — `bio-research` (25 скриптов, вызов из навыка).

   акта нет; нужен перечень реальных контрагентов и режимов.

   нового ревью — S12 это форсирует, молча подменить содержание нельзя.
